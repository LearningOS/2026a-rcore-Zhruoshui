# lab2（ch4：地址空间）实验报告

## 一、功能总结

在引入 SV39 分页机制的内核上恢复了 `sys_get_time` 与 `sys_trace`，并实现了 `sys_mmap`/`sys_munmap` 匿名内存映射：

1. `sys_get_time`：通过 `translated_byte_buffer` 按页翻译用户地址，把 `TimeVal`（16 字节，可能跨页）逐字节写入用户缓冲区；
2. `sys_trace`：读/写一字节前先在当前任务页表中做虚实转换，并检查地址为规范低半区地址、叶子 PTE 有效且具备 R/W 权限，否则返回 -1；查询系统调用次数的语义沿用 ch3（在 syscall 分发入口处先计数，本次 trace 调用自然计入）；
3. `sys_mmap`：校验 start 页对齐、prot 仅含 R/W/X 且非 0、目标区间与已有映射不重叠，按页向上取整后以 Framed 方式插入新的映射区域（自动置上 PTE_U 位）；
4. `sys_munmap`：先确认区间内每一页都已映射（注意框架的 `translate` 对无效叶子 PTE 也返回 Some，需要显式检查 valid 位），再解除映射、回收物理帧，必要时把被切开的映射区域拆分成两段。

另外在帧分配器中增加了"分配即清零"：munmap 回收的物理帧可能残留旧的页表项（valid 位为 1），一旦被复用为页表节点会制造出"幽灵映射"。

本地通过 `make -C ci-user test CHAPTER=4` 全部 16 项检查。

## 二、问答作业

### 1. SV39 页表项的组成与标志位

SV39 的每个页表项（PTE）为 64 位：高 44 位为物理页号 PPN（三级各 26/26/26 位虚拟页号与之对应），低 10 位为标志位：

- V（bit 0）：有效位，该 PTE 是否有效；
- R（bit 1）：可读；
- W（bit 2）：可写；
- X（bit 3）：可执行；
- U（bit 4）：用户态（U-mode）是否可访问；
- G（bit 5）：全局映射，切换地址空间时无需刷除（如跳板页）；
- A（bit 6）： Accessed，该页被访问过（硬件或软件维护）；
- D（bit 7）：Dirty，该页被写过；
- RSW（bit 8-9）：保留给软件使用。

其中 A/D 位用于页面置换，R/W/X 组合若为全 0 则表示该 PTE 是指向下一级页表的中间节点。

### 2. 缺页

**哪些异常可能是缺页导致的？** `LoadPageFault`（取数/读内存）、`StorePageFault`（写内存）、`InstructionPageFault`（取指令）三类异常都可能由缺页触发。

**发生缺页时相关寄存器：** `scause` 置为对应异常编号（13/15/12）；`stval` 保存引发缺页的虚拟地址；`sepc` 为触发异常的指令地址；`sstatus.SPP` 指示陷入前的特权级；`satp` 指示当前使用的页表。

**Lazy 策略的好处：** 按需分配/加载避免了为尚未访问的页面提前做页表操作和内存拷贝——程序申请的内存常常远大于实际使用的部分（如申请 10G 只用 1M），惰性策略把开销推迟到真正访问时，可以节省大量物理内存、页表内存和 I/O 时间，也加快了进程启动速度。

**10G 连续内存对应的 SV39 页表开销估算：** 10GiB = 2.5M 个 4KiB 页面，每个叶子 PTE 8 字节，叶子级共约 20MB；每张中间页表（4KiB）管理 512 项，故二级页表约 2.5M/512 ≈ 5K 张 ≈ 20MB，一级页表可忽略。总计约 **40MB 量级** 的页表内存。

**如何实现 Lazy 策略：** mmap 时只记录"该虚拟区间已批准映射"的元数据（起止地址、权限），不分配物理帧也不写 PTE；首次访问该区间时触发 PageFault，陷入内核后由缺页异常处理程序检查 stval 是否落在某个已批准区间且权限相符，是则分配物理帧、填写页表项，最后返回并重新执行触发异常的指令；否则杀死进程。

**swap 情况下页面失效在 PTE 上的表现：** 页被换出到磁盘后，其 PTE 的 V 位被清 0（无效），PTE 其余位可复用来记录该页在磁盘上的位置（如 swap 分区偏移），访问时触发缺页，由内核据此把页换回内存并恢复 PTE。

### 3. 双页表与单页表

**单页表情况下如何更换页表？** 用户线程和内核线程共用一张页表，因此用户态/内核态切换（trap/return）时不需要更换页表，只有进程（线程）之间切换时才需要：在上下文切换中把新进程页表根物理页号写入 `satp` 并执行 `sfence.vma`。

**单页表下如何控制用户态无法访问内核页面？** 利用 PTE 的 U 位：内核所在页面的 PTE 不置 U 位，U-mode 访问这些页会触发缺页异常；同时可借助 PMP 进一步限制。

**单页表的优势：** trap 进入内核时无需切换页表、无需跳板（trampoline）代码，减少了两次 `satp` 写入与 `sfence.vma` 的 TLB 冲刷开销，内核访问用户内存也无需跨页表翻译，系统调用路径更短、更快，实现也更简单。

**双页表实现下何时需要更换页表？** 每次用户态 trap 进入内核（在跳板页中切换为内核页表）和内核返回用户态（切换回用户页表）时都要更换页表；本内核中即 `__alltraps`/`__restore` 里通过 `csrw satp` + `sfence.vma` 完成切换。若我写一个单页表操作系统，只在进程切换（调度器选中新进程）时更换页表即可。

## 四、实验感想（optional）

ch4 的两个坑都很有教育意义：一是框架的 `PageTable::translate` 对无效叶子 PTE 也会返回 `Some`，任何依赖它做"是否已映射"判断的逻辑都必须显式检查 valid 位；二是引入帧回收（munmap）后，若不在分配时清零，残留 valid 位的旧页表项会让复用帧的新页表出现"幽灵映射"，这类由脏数据引起的错误极难定位，教训是"回收的资源不能带着旧状态进入下一个生命周期"。
